# EP001 Creator Correction — Secondary Object Information Depth

Date: 2026-10-03
Status: ACTIVE

The creator wants narration to go beyond generic purpose descriptions for both main and secondary Spline objects.

## New rule

When an active object or secondary card appears in the Spline story, narration should explain:
- the exact object/card name shown in the diagram;
- what kind of information it contains or represents;
- one or more concrete examples of that information when the diagram supports them;
- why that information is needed at this point in the login journey;
- how it helps the next component or decision.

Avoid protocol-level jargon and avoid treating the objects as a glossary. The narration should remain simple and story-driven, but concrete enough that viewers understand what is actually inside each object.

## Example direction for Request Assembly

For the visible secondary card above Request Assembly:
- `Headers` includes examples such as `User-Agent` and `Accept`.
- `Payloads` can be represented as `JSON` or `Form` data.
- `Request Context` includes examples such as `Timestamp` and `Source`.

The narration should explain what those examples mean in plain language and why the receiving side benefits from them.

This rule applies from SHOT 02 onward and should be preserved in all future script drafting unless explicitly overridden.
