# EP001 Memory Event — Explain Object Contents in Narration

Date: 2026-10-03
Status: ACTIVE

Creator correction: from SHOT 02 onward, when an active main or secondary object is introduced, narration should not stop at naming its purpose. It should also explain what information the object actually contains, using concrete examples visible in the current Spline diagram.

Rule:
- Explain the object in plain language first.
- Name the exact diagram term.
- Explain what information it contains.
- Give at least one concrete example of that information when useful.
- Explain why that information matters for the next step.
- Keep protocol/framework detail out unless needed for understanding.

For Request Assembly, explicitly cover Payload, JSON/Form, Headers, User-Agent/Accept, Request Context, Timestamp/Source with concrete content examples and a final integrating sentence that turns the details into one mental model.

Clarity has priority over preserving the previous shorter timing budget. If the narration needs more time, expand the shot rather than speeding up delivery.
