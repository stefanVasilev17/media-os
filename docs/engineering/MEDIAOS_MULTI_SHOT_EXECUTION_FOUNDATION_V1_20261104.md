# MediaOS — Multi-SHOT Execution Foundation v1 (2026-11-04)

**Director priority:** one reviewed and locked full-episode Episode Package → Director-approved per-SHOT voice Takes → all-SHOT real HEAR → SEE Voice Readiness → finite Director OpenAI authorization → **ONE episode-level job** with all SHOTs, not repeated SHOT-by-SHOT clicks. This handoff is a batch-execution foundation, **not** a claim that OpenAI code agents, GitHub PR generation, render automation or final assembly execute yet.

## What this release implements

1. **Flyway V117**, additive to V116: `episode_multi_shot_execution_job` stores one immutable Director-confirmed execution input per one-use authorization and client request UUID, including source+readiness hashes, strict episode-local Remotion code scope, approved USD/token/attempt ceilings, authenticated Director actor/preflight and an exact source manifest. `episode_multi_shot_execution_task` captures ALL in-order SHOTs with their current script revision, Director-approved current Take UUID, measured audio duration, every verified narration cue with start/end, and original approved visual story. `episode_multi_shot_openai_usage` is a durable reserved/settled/uncertain/no-charge usage ledger; it records attempts, reservation bounds, actual usage **only when a future provider worker reports it**, and provider request IDs. One unresolved paid attempt per job, one prepared job per episode. No legacy tables or EP001/EP002 content overwritten.
2. **Director-only authenticated endpoints** `GET /api/v1/episode-packages/{packageId}/execution-jobs`, `GET .../execution-jobs/{jobId}`, `POST .../execution-jobs/prepare`, and `POST .../execution-jobs/{jobId}/cancel`. POSTs require audited Global Creation Preflight. Prepare requires `requestId`, `authorizationId`, the exact current Voice Readiness fingerprint and explicit `confirmNoProviderExecution=true`. Server locks SHOT rows in stable order, recomputes whole-episode Voice Readiness, requires the grant to still be valid and unexpired, asserts full ordered SHOT scope, immutable source SHA, same fingerprint, exact allowed `stefanVasilev17/media-os` repository and episode-local `remotion-engine/src/episodes/epNNN/` code prefix. No EP001/EP002 imported package can be prepared.
3. **Atomic consumption:** Create one job+every SHOT task and update the Director authorization to `CONSUMED` with `consumed_at` in ONE PostgreSQL transaction. Failed transactions roll back all changes; repeated UUID requests return the same job only if the identity and exact authorization/fingerprint match. New requests with the same consumed grant are rejected. A cancel only works in `PREPARED_NO_DISPATCH`, leaves the authorization consumed and marks SHOT tasks cancelled; another job requires a fresh Director budget approval. The job remains `PREPARED_NO_DISPATCH`, tasks remain `AWAITING_AGENT_IMPLEMENTATION`. No automated agent dispatch.
4. **Internal, not publicly callable `EpisodeMultiShotOpenAiUsageLedger`**: only a *future vetted worker* may call reservation/settlement methods. Provider dispatch is controlled by `mediaos.episode-executor.provider-dispatch-enabled:false` (default OFF), and even when enabled a ledger reservation requires a separately transitioned `RUNNING` job and `RUNNING` task, which no current API can create. Reservation is committed before any future provider call; it rejects duplicate request IDs, unbounded estimated USD/tokens, exceeded caps, attempt exhaustion and a prior `RESERVED` or `UNCERTAIN` call. In future workers, `SETTLED` can store actual USD/token use and detect over-reservation, `UNCERTAIN` freezes further calls and `NO_CHARGE` requires verified zero provider usage; attempts count even if zero charged. The UI shows at-risk usage; **actual provider reconciliation and real paid dispatch do not happen in v1**. These ceilings cannot guarantee provider billing until the real worker uses the ledger correctly.
5. **Director UI:** `EpisodeMultiShotExecutionPanel.tsx` below `AI Production Authorization`, in the EP003+ imported package screen. It shows current Voice Readiness, a matching unused approval, one `Prepare all SHOT tasks — no provider calls` action with final confirmation, source/SHOT/Take scope, zero-spend ledger, previous jobs and explicit cancellation of an unstarted job. It does **not** have a Start Agent button and does not send any OpenAI/TTS/Remotion provider request.

## Safety / scope

- The protected EP001 scene assets, EP002 Director-LOCKED SHOT01, existing voice Takes, locked original scripts and approved visual sources remain unchanged.
- Never interpret a Director authorization `CONSUMED` or job `PREPARED_NO_DISPATCH` as external OpenAI execution or cost already incurred. All jobs have `providerDispatchEnabled=false` and `canStartAgent=false` in this release.
- Current whole-episode manifest captures approved visual source/voice/cue data but **not** a validated reusable-asset/dependency registry or pinned Remotion engine/asset Git SHA. This means it is not safe for actual automatic code writes yet. `assetDependencyStatus=AWAITING_REUSABLE_ASSET_DEPENDENCY_INVENTORY` and `executorStatus=NO_OPENAI_OR_GITHUB_EXECUTION` are explicitly stored. Subsequent worker must reject changed source or voice fingerprints, changed shared assets, expired original authorization, unsafe code paths and incomplete task dependencies before execution.
- No GitHub Actions, provider credits, Railway CPU renders or new QA infrastructure from this release.
- Source tests and checked backend deployment are not Director browser acceptance. PostgreSQL-dependent integration suites may remain skipped. Record exact Java21 Maven totals, frontend TypeScript/Vite and Flyway V117 live rollout in `PROJECT_STATE.md`.
