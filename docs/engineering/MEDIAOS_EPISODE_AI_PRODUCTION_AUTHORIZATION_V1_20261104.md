# MediaOS — Episode AI Production Authorization v1

**Director priority / date:** 2026-11-04 (Europe/Sofia). **FILE → VOICE → AI**. This is the final Director **budget recording/revocation layer** before a separately implemented Multi-SHOT Agent Executor. Do not claim the agent already runs, costs are metered or tokens can be spent through this PR.

## Implemented

- **PostgreSQL Flyway V116**: `episode_ai_production_authorization` stores an immutable approved source/voice `readiness_fingerprint`, original source SHA, ALL ordered SHOT keys (JSONB), constrained episode-scoped source path `remotion-engine/src/episodes/epNNN/`, repository identity, exact `SCOPED_REMOTION_SCENE_PROPOSALS` purpose, finite USD/token/attempt/expiry envelope, verified Director issuer+subject and preflight audit ID, UUID idempotency and timestamps. Only one pending authorization per episode (partial unique index). Separate states: `AUTHORIZED_PENDING_EXECUTOR`, `REVOKED`, `EXPIRED`, `CONSUMED`.
- Java `EpisodeAiProductionAuthorizationService`: `GET /api/v1/episode-packages/{packageId}/ai-authorization` reports the current whole-episode voice-readiness and up to 10 Director-owned authorizations, with effective `EXPIRED`/`STALE_READINESS` state when the current saved voice inputs diverge. `POST .../authorize` requires **explicit Director confirmation**, current 64-hex fingerprint, source-only episode ownership, a valid client-generated UUID, the exact declared budget, audited preflight, and every SHOT voice-ready. Both the authorization and all underlying SHOT rows are transactionally serialized with existing Save/Approve voice mutations. No blind Source/Take hash reuse and no background change triggers the POST.
- Limits in v1: **USD $1.00–$50.00** to two decimals, **1,000–1,000,000 total tokens**, **1–10 attempts**, **15–240 minutes**. These are chosen safe hard ceilings for the **future bounded executor** and are not a price estimate, billable commitment or active runtime meter. One whole-episode scope by default, not per-SHOT manual approval; only episode-local Remotion source proposal paths. No canonical EP001 / Director-LOCKED EP002 file changes, no global shared code edits, no PR promotion, ElevenLabs, Railway CPU rendering or publishing authorized by this record.
- Idempotency: repeat the same UUID only with identical actor, episode, readiness hash and bounds. Different payload/actor/episode returns 409; source or selected Take change forces new Director approval after explicitly revoking a previous unexpired authorization. Expired pending grants are transitioned to `EXPIRED` before a new request. Every approved record can be revoked with a second auditable Director confirmation via `POST .../{authorizationId}/revoke`.
- **No executor consumption endpoint:** the stored state is `AUTHORIZED_PENDING_EXECUTOR`. Even on successful approval the response has `canStartAgent=false`, `executorConnected=false`. The read-only readiness endpoint **also** remains `agentExecutionAuthorized=false`. Neither GET nor POST invokes OpenAI, ElevenLabs, GitHub Actions, Remotion renderer or Railway deploy.
- React Director panel beneath **Episode Voice Readiness** displays whole-episode readiness and source snapshot, constrained budget inputs, explicit consent checkbox + final confirmation, approval history, expiry, stale/revoked state and revoke action. Refresh after a voice Save/Generate/Approve; no paid calls on mount/refresh. No new provider subscriptions or services.

## Security contract for the NEXT Multi-SHOT Executor (not yet implemented)

An authorization record does NOT itself provide unlimited API access or a complete operational rate limiter. When implementing the executor, treat a row as **necessary but insufficient**. Before the FIRST external OpenAI API call it MUST:
1. Run in a guarded transaction, lock the package SHOT rows as in `authorize`, recompute the current all-SHOT Voice Readiness fingerprint, source SHA, selected Takes and cue times; reject stale/unready/expired/revoked/consumed records. Enforce repository and episode-only path allowlist.
2. Atomically claim the row ONCE by marking `CONSUMED` with a unique job, before dispatch. Constrain the entire job to the exact recorded USD, total tokens and attempt budget (including retries), with durable per-request reservations, measured usage reconciliation, conservative `UNCERTAIN` outcomes after ambiguous calls and a fail-closed stop if a cap is approached or exhausted. The current v1 stores ceilings but **does not yet meter API usage**.
3. Generate source proposals only to an isolated GitHub branch/PR. Run controlled tests (never GitHub Actions). PR merge, Railway backend/worker deployments, ElevenLabs and Remotion CPU each require separate Director review and explicit cost/permitted action gates.
4. Re-authorize after source, audio, Take, original visual package version, shared asset dependency or renderer source revision changes. **The present readiness fingerprint covers source narration/selected Take/alignment/story, not all future shared-asset versions**; the executor must extend its production-input fingerprint to include pinned Remotion and asset dependency SHA before using it.
