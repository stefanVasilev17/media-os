# MediaOS — Live Git Dependency Pin + Typed Multi-SHOT Manifest v1

Date: 2026-11-04 · Director workflow: FILE → VOICE → BUDGET → one all-SHOT job → verified dependencies → separately approved paid AI generation. This release only implements the **read-only Git/production-input verification layer**, not paid OpenAI generation, GitHub code writes or Remotion render.

## Implemented

- `RemotionGitDependencyPinService` uses a GET-only GitHub REST metadata client. On explicit user invocation it reads the trusted repository `stefanVasilev17/media-os` current `main` HEAD SHA, and reads the exact file Git blob SHA at that commit for every registered Architectural Thinking primitive source, trusted `registry.ts`, import barrel, design tokens, Remotion package+TypeScript configs, `Root.tsx` and two Director-LOCKED EP002 SHOT01 source files. The 15 historical Director-reviewed assets must match their original blob SHA; drift blocks. Shared integration files not in the historical catalog are dynamically pinned to the same exact HEAD SHA (not silently assumed unchanged). A canonical ordered dependency SHA-256 binds repository+HEAD+catalog+each checked Git blob. The catalog's historical source commit is **not** falsely treated as a live pin.
- A missing/private repository, GitHub 401/403/404/timeout/rate limit, invalid HEAD SHA, missing file metadata, unsafe path or mismatched original asset blob is a **fail-closed blocker**, not a permission to continue from historical hashes. Optional read-only `MEDIA_OS_GITHUB_READ_TOKEN` environment variable may enable read access if the repository is private; the token is never returned to UI or persisted. Do not change production variables or grant credentials without explicit Director action. The backend never attempts a GitHub write.
- `EpisodeCodeWorkerBatchManifestService` combines the existing V117 job snapshot and PR #172 read-only all-SHOT preflight with approved **historical working narration revision**, editorial voice direction, current approved Take UUID, measured audio seconds, verified 30fps HEAR→SEE cue frame boundaries, original Director-approved visual story, explicit registered reuse components, unresolved/new asset keys, exact new episode-local output path and fixed component export for every ordered SHOT. It validates job/source/take/duration identity on every SHOT. Narration, asset names and visual directions are untrusted **data**, never instructions granting tool execution.
- Manifest carries pinned repository commit, asset-catalog SHA, canonical Git dependency SHA, overall production input SHA and transparent per-file Git comparison evidence and blockers. Input hash is only supplied if the Git pin is actually verified. If job cancelled, current voices stale, any asset unresolved or Git drifted, the manifest is `SOURCE_MANIFEST_BLOCKED`; otherwise `SOURCE_MANIFEST_VERIFIED_WAITING_FOR_SEPARATE_DIRECTOR_START`. **Both cases** return `providerDispatchEnabled=false` and `canStartAgent=false`. The purpose is to create a reliable preview and later dispatch input, not to authorize it today.
- Read-only Director-scoped endpoint `GET /api/v1/episode-packages/{packageId}/execution-jobs/{jobId}/code-worker-batch-manifest`. An explicit button in `EpisodeCodeWorkerPreflightPanel` starts the Git metadata read and shows source path/hash changes, blocker reasons, shot-by-shot outputs, selected Take, camera/story and real cue frames. It is deliberately **on demand**, not fetched automatically on page load, to avoid accidental GitHub rate limits. No paid API calls, no source modification.
- Separate zero-provider unit tests for Git baseline matching, deterministic hashes independent of file ordering, missing/private GitHub, unsafe traversal, source changes, stale selected voice Take, edited narration revision and changed measured audio duration.
- The existing EP002 SHOT01-specific `remotionSceneContract.ts` is untouched. Future output still obeys `docs/contracts/mediaos-generated-remotion-scene-proposal-v1.schema.json`; schema validation alone is not code safety.

## Known limitations and required next step

- This is **not yet the actual Multi-SHOT Code Worker**. The backend has NO public `Start AI` route, no provider pricing/usage dispatcher, no GitHub branch/PR generation and no isolated compile/test of generated TSX. No GitHub Actions or paid Railway CPU rendering is triggered. A verified Git pin means "these files matched this particular Git commit at that read", not that future source cannot change; the executor must **re-fetch and compare the pinned HEAD and protected blobs immediately before any dispatch and GitHub write**.
- A private repo without server-side `MEDIA_OS_GITHUB_READ_TOKEN` can be inspected through ChatGPT's connected GitHub app but **will fail closed in the backend** until the Director expressly sets up a suitable read-only GitHub credential. GitHub connector access inside ChatGPT is not automatically a backend credential.
- Asset keys absent from the reviewed 15 primitives (e.g. `REDIS`, `PAYMENT_GATEWAY`) remain explicit missing-new-asset decisions. Do not allow generated code to silently import nonexistent components. Existing items marked `EXISTING_REQUIRES_DIRECTOR_REVIEW` must be reviewed before final scene acceptance.
- The reusable source pin does not itself authorize GitHub writes or prove that a proposed TSX is compilable. The NEXT milestone is a separately audited Director Start gate, pinned model/pricing and per-attempt OpenAI ledger reservation/reconciliation, agent-produced exact-path proposals, isolated TypeScript/Remotion checks and a Director-reviewed GitHub PR. Separate cost consent for renders, TTS and publishing remains mandatory.
- Director browser validation of a real imported EP003+ package with approved voice Takes is still pending. Build/test and Flyway/worker health should be verified and reported without claiming this acceptance.
