# MediaOS — Reusable Remotion Asset Registry + Multi-SHOT Code Worker Preflight v1

**Date:** 2026-11-04 · **Director instruction:** prioritize actual batch-first whole-episode visuals; do not ask the Director to generate every SHOT individually. This release improves the **technical prerequisites** for an actual safe code worker. It **does not** yet call OpenAI, create GitHub PRs, edit code or render a scene.

## Why a new contract is needed

The existing `remotion-engine/src/contracts/remotionSceneContract.ts` is explicitly **EP002 SHOT01-only** and Director-LOCKED. The existing `remotion-engine/src/components/architectural-thinking/registry.ts` lists **12 LOCKED components** from EP001, while the current source also exports additional reference-only primitives `ATControlledRealismLayer`, `ATArchitectureRevealBridge`, and `ATBackendNode`. The worker must reuse these components **by importing without editing them**, not invent components with the same name, overwrite locked sources, or apply EP002-only timing contracts to EP003+.

## Implemented — real repo evidence and read-only full-job planning

- `backend/src/main/resources/episode-production/remotion-reusable-assets-v1.json`: catalog of **15 actual React/Remotion exports**, with exact source path and **Git blob SHA-1** observed at source commit `24f537d7eab6f819261edb649c41a93d2ce7c844`, plus trusted import path, explicit editorial aliases and status. The first 12 are `DIRECTOR_LOCKED_REUSE_ONLY`, and the other 3 are `EXISTING_REQUIRES_DIRECTOR_REVIEW`. These hashes are historical **source evidence**, not proof that a later checkout still contains the same source. The catalog itself has a SHA-256 fingerprint.
- `RemotionReusableAssetRegistry` reads this fixed classpath document at startup; rejects broken schema/version/source paths, invalid Git SHA, duplicate asset IDs or conflicting aliases. Only explicit asset keys map to registered components. Example: `PHONE_LOGIN → ATPhone`, `CAMERA_RIG → ATCameraRig`, `AUTH_NODE → ATPrimaryNode`; `REDIS` and `PAYMENT_GATEWAY` are intentionally **missing new-asset proposals**, not fabricated imports.
- `EpisodeCodeWorkerPreflightService` reads **ALL** stored SHOT tasks in one immutable V117 job, only after verifying Director ownership through the existing execution service and reading current all-episode voice readiness. It checks original visual beat/cue counts and order; computes `durationInFrames = ceil(realMeasuredDurationSeconds * 30)`, converts each verified ElevenLabs cue time to a bounded frame range without inventing voice timings, matches each SHOT's source `assetKeys` and every beat's `assets` against the trusted asset registry and returns unresolved keys. It proposes **new episode-local file paths only**, e.g. `remotion-engine/src/episodes/ep003/Shot07GeneratedScene.tsx`; strict path rules exclude EP001/EP002, other repositories and traversal.
- New **Director-only read-only GET** `/api/v1/episode-packages/{packageId}/execution-jobs/{jobId}/code-worker-preflight`. Response includes trusted registry version/historical base commit/catalog hash, immutable source and current voice fingerprints, a tentative production-input hash, dependency blockers, all proposed scene paths, actual cue frames, selected voice Take and unresolved asset declarations.
- New `EpisodeCodeWorkerPreflightPanel` in **Episodes → Imported Episode → Multi-SHOT Execution Foundation → prepared job → Review Reusable Assets & All SHOT Plans**. It loads on-demand, shows each asset's reuse/review/new status, missing keys, scene voice timing and **explicit AI dispatch disabled** notices. Opening it never makes an OpenAI, ElevenLabs or Remotion worker call.
- **Generic future output envelope:** `docs/contracts/mediaos-generated-remotion-scene-proposal-v1.schema.json` specifies an EP003+ scene proposal with exact episode-local TSX path, source/catalog/Git hashes, frame count, selected Take, real cue frame positions and asset dependency references. Passing a schema is **not a substitute for AST/static review, typecheck, sandbox isolation, generated code tests and explicit Director PR merge approval**.

4. Only then connect a pinned-model provider with **actual OpenAI usage measurements**, conservative pre-dispatch reservations in `EpisodeMultiShotOpenAiUsageLedger`, real provider request reconciliation and **fail-closed UNCERTAIN paid request** handling. Prevent concurrency, retries and unknown maximum charge. A real provider price model must be pinned/verified and must never claim false spend guarantees.
5. The worker can create **one isolated GitHub branch and per-SHOT proposed files** for all required SHOTs, with no writes outside the new episode path; run isolated `tsc --noEmit`/Remotion validation without GitHub Actions, then open a PR for Director review. Separate approvals are required before merge, Railway CPU renders, assembly and publishing.
