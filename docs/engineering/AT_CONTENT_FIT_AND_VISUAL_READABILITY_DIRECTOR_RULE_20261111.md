# Architectural Thinking / MediaOS — Director permanent visual readability rule

**Status: Director-requested visual production rule (2026-11-11). Applies to SHOT10 and all FUTURE episode scenes and authoring agents; not retroactively to locked MP4s.**

## Content-fit is mandatory, NOT optional

1. Every new speech-driven blue, amber, mint, or red information container, callout, caption pill, tooltip, readout, and status badge **must be fitted to its ACTUAL displayed text**, not fixed to the largest possible panel size. Horizontal and vertical visible padding should be proportional and consistent; no large empty boxes. A multi-state panel must **smoothly animate its width AND height** on every spoken-state change, frame-deterministically from real ElevenLabs character-aligned cue frames. Avoid fixed 445x148-style containers for short labels. Limit sizes to the safe regions of the 1920x1080 Living Architecture map; never cover infrastructure nodes, or overlap another panel. Content must not clip in intermediate animation frames (delay/reveal copy until the container has room).
2. **Do not add microscopic explanation text.** Information intended for 1920x1080 YouTube viewing must be immediately legible at reduced playback size. The expected minimum for newly authored secondary on-screen copy is **18px** at 1080p; primary copy should normally be 20px or larger; reserve smaller lettering only for intentionally minor, already locked legacy content reproduced at an exact shot seam. If secondary explanation duplicates visible animation, narration, or another label, **delete it instead of making it smaller**.
3. Every information panel must answer a meaningful visual question. Remove redundant labels/cards rather than filling empty regions. Specific Director rejection: **remove the SHOT10 “DATABASE QUEUE · DRAINING” card entirely**; a voice-linked queue animation and compact, honest numeric comparison can communicate the same fact. Remove small under-card footnotes (“REQUEST-LEVEL EVIDENCE”, “QUEUE SHRINKS ONLY IF…”, tiny DB readout captions), not just hide them behind another container.
4. The opening frame of a NEW shot must reproduce the final frame of the PREVIOUS Director-LOCKED shot. The locked closing hold is a deliberate exception to new-shot resizing: do not retroactively edit the locked shot or make its first-frame handoff jump. Fade old legacy microcopy promptly **after** frame 0 and transition naturally to correctly sized new-shot panels, without editing voice, shifting real HEAR→SEE timestamps, changing world geometry, or adding fake new services.
5. Preserve 1 Phone, 1 Gateway, 1 Load Balancer, 3 Auth and 1 shared User Database for EP002; no fictitious database capacity increase or resuming timed-out Login. Dynamic containers are *annotations* on the living map, not detached analytics slides.
6. **Gate every new scene with code tests** that enumerate actual intended label strings, verify content-specific dimension variation (more than one width), measured text width plus padding within the container max, non-clipping and node-safe positions, cue-bound animations, no small live-copy font sizes, no removed placeholder panels, and exact LOCKED frame 0 handoff. The agent must run the full real Railway Remotion Docker build including scoped and full Node tests before recommending a paid render. A successful build does NOT replace Director MP4 visual acceptance.
