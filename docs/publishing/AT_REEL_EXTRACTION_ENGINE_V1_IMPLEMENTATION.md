## Workflow

Single full-width list, ready/requested clips first, suggested full-SHOT cuts next, other SHOTs collapsed, one preview at a time; Preview / Extract / Lock / Download. Custom cut uses decimal seconds converted to exact 30-fps frames, start inclusive/end exclusive. Source preview is not an exported file. Only actual READY MP4s may be locked; lock requires explicit Director review confirmation and exact output hash. Earlier-master clips are separate and do not count toward the current minimum. No automatic extraction or external publishing. UI includes original-format 16:9 warning: not automatically eligible for YouTube Shorts; square/vertical packaging requires separate explicit Director approval. No packaging implemented here.

## Backend and storage
Additive V133 episode_reel table: exact package, film ID, master SHA, frame interval, title, state, Director audit/actor, private object manifest, technique, lease. Authenticated owner-only GET and explicit audited POST extraction/lock. Duplicate range requests idempotent; failed jobs require explicit retry, no automatic rerenders. Existing backend assembly scheduler processes a single bounded technical extraction globally, waits while full-film assembly jobs are queued/running; no new service/worker/bucket or separate Remotion render. Existing private MP4 object store upload with SHA-256 readback, reel retention class and protected range streaming; DB stores metadata only. Exact source checksum verified after streamed scratch download. Stream copy only when the requested start is a true video keyframe, then require exact decoded pixels and PCM hash plus frame/audio clocks. Initial build `db1d559c-a369-47d6-a362-68541967610e` failed the non-keyframe regression because MP4 edit-list preroll could satisfy decoded equality; keyframe precheck now explicitly forces independent technical encoding. Otherwise technical H264/AAC encode only with same original 1080p30 dimensions, duration/decoded count, PSNR >=35 dB and decoded narration waveform/sample-count comparison. Scratch removed on exit; uncommitted uploaded object cleanup guarded by DB reference check. Interrupted jobs lease-expire to FAILED. Operational bounds: input <=1 GiB, output <=128 MiB, interval <=180s, episode retained/reserved budget 2 GiB, fixed per-process timeouts and one active job. This is a byte/resource budget, not creative quota. Automatic retention/cleanup of rejected retained clips and crash-orphan audit remain later hardening; no automatic deletion of locked media. Each extraction downloads master once; batch reuse is not implemented. No provider calls; explicit extraction click authorizes bounded technical CPU/storage, not a new creative render.
